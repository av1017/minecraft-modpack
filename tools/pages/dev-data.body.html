Dev: Data Files

All of the mod's rules live in datapack JSON under data/<namespace>/cvages/, so any datapack (or another mod) can add to them. The built-in ones are written by tools/gen_data.py, gen_quests.py and gen_books.py: edit the tables in those scripts, not the JSON. After a change: rebuild, or for a datapack on a running server, /reload.

ages seeds item_rules tags disciplines books badge_sources tuning loot, recipes, quests

cvages/ages/<id>.json

{ "order": 2, "name": "Iron Age", "color": "#D8D8D8",
  "badges": 1,                      distinct gym badges the group needs
  "group_quests": [],               advancement ids; all needed, anyone can earn them
  "dimensions": [] }                dimensions locked until this age

Ages unlock in order; an age needs the previous one. Generated from AGES in gen_data.py.

cvages/seeds/*.json

{ "stone": ["minecraft:cobblestone", "minecraft:coal", ...],
  "iron":  ["minecraft:iron_ingot", ...], ... }

Items pinned to an age; every other age is worked out from recipes. Recipes that make a seed are ignored. From SEEDS.

cvages/item_rules/*.json

{ "rules": [
  { "match": "cobblemon:great_ball", "policy": "must_learn" },
  { "match": "/cobblemon:.*_berry/", "age": "wood" },
  { "match": "@poke-clothing", "category": "none", "discipline": "tailoring" },
  { "match": "#minecraft:trim_templates", "discipline": "blacksmithing" } ] }
FieldValues
matchns:item, #ns:tag, @modid, or /regex/ (matched against the full id)
agean age id: overrides the computed age
categorynone, tool, melee, armor, ranged, shield: overrides the gear classifier
policyauto, must_learn, book, exempt
disciplinea discipline id (crafting needs it); "" clears one

Rules apply in file order and later rules win, so exceptions go after the rule they except. Built-in files: cobblemon_essentials.json (COBBLEMON_RULES) and decor_books.json (DECOR_BOOK_RULES).

Tags

  • #cvages:must_learn: base policy must-learn (furnace, anvil, enchanting table...). From MUST_LEARN.
  • #cvages:exempt: never gated (our book and crate items, the trainer card).

Tags set the starting policy; item rules override them.

cvages/disciplines/<id>.json

{ "name": "Cooking", "age": "stone",
  "proxy_items": ["farmersdelight:cooking_pot", ...],   holding one lets a master teach it
  "gated_blocks": ["farmersdelight:cooking_pot", ...] } these won't open until learned

The knowledge key is cvages:discipline/<id>. Proxy items and blocks accept #tags; ids from missing mods are ignored. Enchanting has no gated blocks: its table and anvil checks are in mixins. From DISCIPLINES.

cvages/books/<mod>/<family>.json

{ "title": "Handcrafted: Chairs, Corner Trims & Couches",
  "age": "wood",                     earliest age it can be read
  "items": ["handcrafted:acacia_chair", ...] }

Book id = <namespace>:<path>. Items from missing mods are dropped; a book left empty is skipped. Generated by gen_books.py from the dump: every craftable BOOK item lands in exactly one book.

cvages/badge_sources.json

{ "leaders": { "brock": ["rctmod:trainers/defeat_leader_brock"],
               "roark": ["rctmod:trainers/defeat_gym_leader_roark_1", "..._roark_2"], ... } }

Leader key → advancements meaning "beat this leader". Distinct keys earned by anyone count as group badges. From leaders().

Loot, Recipes, Quests

  • loot_table/prize_crates/<age>.json (+ extras/<age>.json, loads only with Cobblemon) and loot_table/rewards/crate_<age>.json, maybe_crate_<age>.json: from CRATES, CRATE_EXTRAS, HIDDEN_QUEST_CRATE_CHANCE.
  • Loot functions: cvages:random_book (age: id or current) and cvages:set_crate_age (same).
  • Structure-chest and trainer crate odds are in Java (content/LootInjection.java), because loot tables load before our data.
  • recipe/bushcraft/*.json: from write_bushcraft(); the leaf-bed ones load only with Leaf Beds.
  • advancement/ and function/master/: the quest tab, from gen_quests.py. Hand-made extras go in advancement/custom/ (never deleted by the generator).

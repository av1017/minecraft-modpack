Dev: Architecture

Data comes in as JSON, the server turns recipes into an age for every item, players' knowledge lives in two save files, and a handful of hooks (events and mixins) apply it everywhere a player crafts, mines, fights or travels. Clients get a copy of the age table and their own knowledge for tooltips and prediction.

The Age Resolver

  1. Seeds pin key materials to an age (cobblestone Stone, iron ingot Iron, diamond Diamond...). Recipes that make a seeded item are ignored so loops can't drag it down.
  2. Every recipe becomes "result needs ingredients" (each ingredient is a list of options; the cheapest option counts). Smithing recipes are read through an accessor because they hide their inputs.
  3. Recycling is skipped: smelting gear back into nuggets doesn't tie iron to iron armor.
  4. Recipe loops (ingot ↔ block ↔ nugget) are found as strongly connected components (iterative Tarjan) and solved together: a loop's age is its cheapest way in from outside. A loop with no way in is natural, age 0.
  5. An item's age is the cheapest of its recipes, where a recipe's age is its most advanced ingredient.
  6. Gear without a recipe falls back to its repair material; anything else without a recipe is age 0 ("default").
  7. Tags set the base policy (#cvages:must_learn, #cvages:exempt), then item rules apply in file order, later ones winning.

/cvages why <item> prints the reason and each recipe's ingredient ages. /cvages dump writes the whole table.

Saved State

File (world/data/)Holds
cvages_players.datPer player UUID, per item or discipline key: craft (NONE / NOTES / TAUGHT / MASTER), skill 0-100, discovered, discovery points, discoveryHold, questMastered. Keys are strings, so removing a mod never loses data.
cvages_world.datUnlocked ages, the group's badges (leader keys), completed group quests.

Discipline knowledge uses keys like cvages:discipline/cooking in the same player data. Item stacks carry cvages:quality, cvages:crafter, and for our items cvages:book / cvages:crate_age.

Client Side

  • ClientState applies the two payloads; Knowledge.clientView reads it, so shared code (mining speed, effectiveness) predicts correctly.
  • CvAgesClient adds the tooltip lines (skill, recipe status, discipline, quality, discovery bar).
  • ItemStackNameMixin shows "Strange Object", only on the client thread (a LAN host's integrated server never sees the fake name).
